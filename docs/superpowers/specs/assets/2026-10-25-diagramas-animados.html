Como é feito — três diagramas

Arquitetura

O site é estático e vive na borda da Cloudflare. Quando alguém pede um teste, o navegador chama a API, que passa por um balanceador e cai numa das duas VMs em Go.

Cinza: o site chegando. Laranja: um pedido de teste indo até a API.

Pipeline

Um pull request roda os testes. Na main, a API ganha uma release e o site passa por um portão de aprovação antes do deploy. Se algo der errado, há rollback.

O ponto laranja é uma mudança atravessando o pipeline; o portão "OK?" é onde o deploy espera por aprovação.

Infraestrutura

Rede, duas VMs, balanceador e o registro de DNS da API saem de código Terraform. O estado fica num bucket remoto, então dá para destruir e recriar tudo.

Os recursos aparecem em sequência, como num apply. O site em si (o Worker) é publicado pelo pipeline, não pelo Terraform.
